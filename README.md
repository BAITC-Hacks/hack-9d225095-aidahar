# Точно в формат · #79-lite

Рабочий MVP умного подбора event-подрядчиков Казахстана. Возвращает до трёх карточек с проверяемыми объяснениями, исключает занятых, различает отсутствие категории и отсутствие совпадений. Есть браузерный интерфейс, локальный HTTP API, импорт каталога и сценарии для живого показа.

## Запуск за минуту

Нужен Node.js 20 или новее. Внешних зависимостей, API-ключей и установки пакетов нет.

```bash
npm start
```

Откройте http://127.0.0.1:4173. Для другого порта: `PORT=8080 npm start`.

```bash
npm test
npm run demo
```

Первая команда проверяет алгоритм, вторая запускает шесть показательных запросов в терминале. Интерфейс также содержит кнопки этих сценариев. Сайт работает через HTTP; открытие HTML двойным щелчком не поддерживается из-за загрузки модулей и каталога.

## Что с данными

Полный `hackathon-dataset-anonymized.jsonl` на 66 профилей не был приложен. В `dist/catalog.jsonl` находятся **18 записей**:

- 3 исходных анонимизированных профиля из текста задания: HK-39372, HK-44733, HK-80581. Сохранены описания, цены, флаги и все присланные занятые даты.
- 15 созданных для демонстрации профилей DEMO-001…DEMO-015. У каждого `synthetic: true` и дополнительный `added_for_demo: true`. Они заметно обозначены в карточках. Их короткие календари созданы для проверки сценариев и не воспроизводят сезонную загрузку полного датасета.

`synthetic: false` означает исходную анонимизированную запись, а не подтверждённую личность. Внешних проверок качества и доступности нет. `city_imputed` и `price_imputed` выводятся как предупреждающие метки, а не скрываются.

### Подключение полного каталога

В интерфейсе раскройте «Каталог и прозрачность подбора» и загрузите JSONL, JSON-массив, CSV или TSV. Каталог **заменяется**, а не смешивается с демопрофилями. Файл обрабатывается локально в браузере, не отправляется на сервер и не сохраняется после перезагрузки. Лимит: 10 МБ и 10 000 записей.

Для HTTP API и стартового каталога интерфейса укажите файл при запуске:

```bash
CATALOG_FILE=/absolute/path/hackathon-dataset-anonymized.jsonl npm start
```

Поддерживаются CSV с разделителем `,`, `;` или табуляцией, UTF-8 BOM, кавычки и переносы строк внутри полей. Списки в CSV разделяются `|`. Например, `корпоратив|день рождения`. Пустое `max_hours` читается как `null`. Флаги должны быть `true/false` или `TRUE/FALSE`. Для серверной версии каталог читается один раз при запуске; после замены файла нужен перезапуск.

Браузерный импорт меняет только текущую вкладку; каталог API при этом не меняется. Для постоянной смены каталога опубликованного статического сайта замените `dist/catalog.jsonl` и опубликуйте обновление.

## Пайплайн, который можно объяснить жюри

1. **Валидация**: обязательные поля, конечный положительный бюджет в целых тенге, допустимая длительность, корректная дата в окне 23.09–31.12.2026. Вне окна сервис возвращает понятную ошибку: доступность неизвестна.
2. **Город + категория** задают исходный круг. Пустой круг → `category_absent`. «Зарубежье» не подставляется вместо выбранного города.
3. **Строгая фильтрация**: занятость на дату, цена «от» не выше бюджета, формат в списке, запрошенный язык в списке, достаточный лимит часов. `max_hours: null` не ограничивает длительность присутствия. Пропущенные опциональные параметры не фильтруют.
4. **Ранжирование только допущенных кандидатов**. Пожелания разбиваются на слова длиной от четырёх символов; небольшой явный словарь основ обрабатывает, например, «атмосферный/атмосферные». Никаких случайных чисел и внешних вызовов.
5. **Объяснение из фактов**: свободная по календарю дата, совпавшие условия, запас бюджета и цитата из описания. Выбирается предложение с наибольшим числом совпадений с пожеланиями; при равенстве — первое. Цитата обрезается до 270 символов с многоточием.
6. **Не больше трёх**. При меньшем числе показаны все и причины дефицита. Для пустой выдачи рассчитаны конкретные альтернативы: минимальный бюджет при прочих прежних условиях и ближайшая дата с кандидатом при прежнем бюджете и остальных фильтрах, если такие альтернативы существуют. Ничего не меняется автоматически.

### Формула и детерминизм

```text
баллы_описания = 10 × min(число уникальных совпавших основ, 5)
баллы_бюджета  = 20 × (1 − цена_от / бюджет)
оценка        = баллы_описания + баллы_бюджета
порядок       = оценка ↓, цена ↑, id ↑
```

Баллы — соответствие запросу, не рейтинг качества. Более дешёвый подрядчик может обогнать более дорогого при небольшой разнице совпадений. Без пожеланий порядок определяется ценой и ID. Это прозрачная эвристика, которую нужно калибровать на обратной связи; она не объявляется оптимальной моделью выбора.

Одинаковые данные и параметры дают одинаковые карточки и порядок независимо от порядка строк. Время вычисления интерфейс показывает отдельно и не включает в ответ алгоритма. Подсчёт исключений многопричинный: один профиль может быть одновременно занят и дороже бюджета, поэтому суммы причин нельзя складывать как число людей.

### Честно об AI

В этой версии **нет LLM, эмбеддингов или дообучения**. Поиск по описанию лексический: он не понимает синонимы, отрицания и смысл текста. Описания цитируются как заявления автора профиля. Упоминание слова «вокал» не считается доказательством услуги, если в тексте написано «без вокала»; такая ошибка лексического ранжирования возможна, и полная цитата позволяет её заметить.

Для развития: предварительно вычислить эмбеддинги описаний, оставить строгие фильтры в коде и ранжировать допущенные профили по сходству с брифом; кэшировать векторы и фиксировать версию модели. Генерацию объяснений можно добавить с привязкой каждого тезиса к полям/цитатам и с нынешним шаблоном как резервом. Эта доработка не реализована и не требуется для запуска демо. Выбор простой эвристики снижает задержку и исключает зависимость от API, но ограничивает AI-составляющую для оценки жюри.

## API

Локальный Node-сервер обслуживает `GET /api/health` и `POST /api/recommend`. Развёрнутая статическая версия выполняет тот же алгоритм в браузере, **HTTP API на ней нет**.

```bash
curl http://127.0.0.1:4173/api/recommend \
  -H 'Content-Type: application/json' \
  --data '{"city":"Алматы","date":"2026-11-14","event_format":"корпоратив","category":"Ведущий","budget":1200000,"hours":4,"language":"русский","wishes":"интеллигентный атмосферный"}'
```

Обязательные поля: `city`, `date` (ISO YYYY-MM-DD), `event_format`, `category`, `budget`. Опциональные: `hours`, `language`, `wishes` (до 500 символов).

Успешный HTTP 200 возвращает:

- `status`: `matched`, `category_absent` или `no_matches`;
- `cards`: максимум 3 карточки с `explanation`, `evidence`, флагами происхождения и разложением баллов;
- `total_in_category`, `eligible_count`, `exclusions`;
- `rejected_profiles`: причины по конкретным профилям;
- `message`, `suggestions`, `calendar_window`, нормализованный `query`.

Пустая выдача — обычный результат HTTP 200. Некорректные параметры или JSON → HTTP 400; запрос больше 64 КиБ → HTTP 413. Сервер слушает loopback и предназначен для локального демо, не для публичного промышленного API.

При поддержке браузером WebMCP страница регистрирует `recommend_contractors`: он использует тот же алгоритм и обновляет видимую выдачу. Без WebMCP все кнопки и поля продолжают работать.

## Сценарий защиты за 3 минуты

Все сценарии ниже относятся к включённому демокаталогу. После импорта полного датасета результаты могут отличаться.

| Сценарий | Параметры | Что показать |
|---|---|---|
| Плотная категория | Алматы, 14.11, корпоратив, ведущий, 1 200 000 ₸, 4 ч, русский; «интеллигентный атмосферный» | 4 допускаются из 8; первые 3: Буллма, Алмас, Айша. Буллма выигрывает за совпадения в собственном описании, хотя дороже |
| Другая дата | Только дата меняется на 15.11 | Буллма, Дана, Тимур; Алмас и Айша заняты. Раскрыть причины исключения |
| Редкая категория | Алматы, 14.11, флорист, 250 000 ₸ | 1 из 2: Лепесток; исходный флорист занят; список не дополняется неподходящими |
| Кандидаты есть, подходящих нет | Ведущий, 14.11, 50 000 ₸ | `no_matches`; минимально возможная цена при остальных условиях 420 000 ₸ |
| Категории в городе нет | Алматы, отель | `category_absent`, объяснение относится только к этому каталогу |
| Площадки | Алматы, 14.11, банкетный зал, 1 200 000 ₸ | Два зала; третий занят на дату |

Повторите первый запрос: порядок идентичен. Покажите цитаты, синтетические метки и формулу в «Детали и оценка». Для воспроизводимой терминальной демонстрации используйте `npm run demo`.

## Проверки

16 автоматических тестов: происхождение данных, ранжирование, принадлежность цитат профилю, детерминизм и перестановка входа, смена даты, редкая категория, оба пустых состояния, площадки, язык/часы, точные границы бюджета/часов, неправильные даты, некорректные параметры, равные оценки, JSONL/CSV/TSV, ошибки каталога. Один тест проверяет все строгие ограничения на каждой из 100 дат для трёх плотных категорий.

Проверено также вручную в браузере: заполненная выдача, смена даты, редкая категория и оба пустых состояния; WebMCP — успешный запрос и отклонение даты вне окна без изменения результата. Проверен POST API. В этой среде запуск шести демозапросов занимал примерно 0,1–31 мс на запрос; это не обещание производительности на любом устройстве и не нагрузочный тест.

## Границы MVP

Цена «от» не гарантирует итоговую смету. Нет актуализации календарей, бронирования, заявок, уведомлений, оценок реального качества и сохранения заказов. Доступность считается как отсутствие даты в `busy_dates` **только внутри известного окна**. Для полноценного показа на исходных 66 записях загрузите оригинальный файл и подберите демонстрационные запросы с `npm run demo` или через форму. Демо на 18 профилях не заменяет проверку полного датасета.
